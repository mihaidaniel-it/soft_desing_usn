## Задание 1. Компилирование, выполнимый файл

### 1.1 Удаление временных файлов

```
$ rm -rf bin obj
$ ls
Program.cs  lab02.csproj
```

### 1.2 `dotnet run --no-build`

```
$ dotnet run --no-build
Unhandled exception: An error occurred trying to start process
'.../lab02/bin/Debug/net10.0/lab02' with working directory '.../lab02'. No such file or directory
```

Наблюдение: программа не запустилась. Исходный код (`Program.cs`) нельзя выполнить напрямую —
сначала его нужно скомпилировать в выполнимый файл. Флаг `--no-build` запрещает компиляцию,
а папку `bin` с выполнимым файлом мы удалили, поэтому запускать нечего.
Обычный `dotnet run` (без флага) сначала компилирует проект, а потом запускает результат.

### 1.3 `dotnet build`

```
$ dotnet build
Program.cs(62,6): warning CS8321: Локальная функция "NeverCalled" объявлена, но не используется.
    1 Warning(s)
    0 Error(s)
```

Предупреждение ожидаемое — это функция из задания 2.4.
После сборки снова появились папки `obj` (промежуточные файлы) и `bin` (результат компиляции).

### 1.4 Выполнимый файл в `bin`

```
$ ls bin/Debug/net10.0/
lab02  lab02.deps.json  lab02.dll  lab02.pdb  lab02.runtimeconfig.json
```

- `lab02` — выполнимый файл (на Windows это был бы `lab02.exe`);
- `lab02.dll` — скомпилированный код программы, его можно запустить и так: `dotnet lab02.dll`.

Запуск из консоли:

```
$ cd bin/Debug/net10.0
$ ./lab02
--- 2.1 ---
Hello, Jerry
...
```

Наблюдения:
- .NET установлен в домашнюю папку (`~/.dotnet`), поэтому выполнимому файлу нужна переменная
  `DOTNET_ROOT`. Без нее запуск падает с сообщением `You must install .NET to run this application`.
  Переменная прописана в `~/.zprofile` (см. lab01), после этого `./lab02` работает.
- При двойном клике в Finder файл открывается в Terminal. Окно после завершения программы
  по умолчанию не закрывается само (пишет `[Процесс завершен]`), поэтому `Console.ReadKey()` в конце не нужен —
  он нужен на Windows, где консольное окно закрывается сразу.

## Задание 2. Базовые инструкции

Полный вывод программы:

```
--- 2.1 ---
Hello, Jerry
--- 2.2 ---
A
B
C
A
B
C
A
B
C
--- 2.3 ---
A: начало
  B
  C
A: конец
A: начало
  B
  C
A: конец
A: начало
  B
  C
A: конец
--- 2.4 ---
NeverCalled не вызвана, ее строка не напечаталась.
--- 2.5 ---
DefinedFirst вызывает DefinedLater:
  DefinedLater выполнилась
```

### 2.1
`Console.WriteLine("Hello, Jerry");`

### 2.2
Функция `PrintABC` печатает `A`, `B`, `C`. Она вызывается 3 раза, после каждого вызова —
`Thread.Sleep(500)` (пауза 0.5 секунды).

### 2.3
Функция `A` вызывает `B` и `C`, основная программа вызывает `A` три раза.
Инструкции выполняются по порядку: при вызове `A` управление переходит в `A`,
из нее в `B`, после окончания `B` возвращается в `A` и идет в `C`, затем обратно в основную программу.

### 2.4. Что будет, если функцию нигде не вызвать?
Она не выполнится никогда. Определение функции только описывает ее инструкции и имя,
а выполняются они лишь при вызове. Функция `NeverCalled` в программе есть, но ее текст
в консоли не появился. Компилятор даже предупреждает об этом: `warning CS8321 ... объявлена, но не используется`.

### 2.5. Важен ли порядок определения функций?
Нет. Функция `DefinedFirst` определена в файле раньше, чем `DefinedLater`, но спокойно ее вызывает.
Точно так же основная программа вызывает все функции до того, как они определены ниже в файле.
Компилятор сначала видит все определения функций, поэтому сослаться можно на любую из них.

(С переменными так нельзя: переменную нельзя использовать в строке выше ее определения.)
